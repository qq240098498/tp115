# tp115 时区与时间换算工作台

一个本地小工具：把各地时区连同夏令时规则登记进来，再把某一个时刻换算到所有已登记的时区，页面上直接看出各地是当地的几点、谁的日期已经翻到前一天或者后一天、跟来源时区差了几个小时。手上拿着对方那边定好的当地时刻时，也可以反推出我们这边是几点几分、哪一天；对方那一刻若正好落在夏令时回拨的重复小时里，前后两个实际时刻都会列出来，每个结果都会再正推一遍与对方输入对账。时区名写得不合规矩、偏移超出范围、夏令时偏移不比标准偏移靠前、开始与结束两段规则写得一模一样、结束年份早于开始年份，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5115>

端口固定为 `5115`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 时区档案区列出时区名称、显示名称、标准偏移、是否实行夏令时、夏令时偏移、切换规则、生效年份与备注；可以按是否实行夏令时筛选，也能按名称、显示名或备注搜索
2. 点新建档案填上时区名与偏移；实行夏令时的档案还要把夏令时偏移与开始、结束两段切换规则（第几个星期几的几点几分）以及生效年份填上
3. 换算台选好日期、时刻与来源时区，点换算一遍，页面列出每个已登记时区的当地日期、当地时刻、星期、与来源是否同一天、偏移以及跟来源时区差多少
4. 反推台选好对方时区、对方定好的当地日期与时刻，以及我们这边时区，点反推，页面给出我们这边对应的日期、时刻、星期、与对方是否同一天，以及双方当时各自生效的偏移；对应两个实际瞬间时两个都列出并标清先后，每个结果都附一遍正推校验的结论
5. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 换算口径

- 换算按登记的标准偏移进行：先把输入的当地时刻减去来源时区的标准偏移得到基准时刻，再逐个时区加上各自的偏移
- 每个时区的当地日期与时刻都由基准时刻加上该时区的偏移算出，日期是否翻到前一天或后一天按公历日比较
- 与来源时区的时差按两边偏移的差值给，整小时只写小时，带分钟的把分钟也写出来
- 结果按偏移从小到大排列，来源时区那一条在页面上会标出来
- 档案里登记了夏令时规则不等于换算时已经计入夏令时，规则本身如何落到具体日期上需要另行处理

## 反推口径

- 反推把对方的当地时刻按对方时区当时实际生效的偏移（含夏令时）折算：分别拿标准偏移与夏令时偏移试算，哪个偏移折算出的瞬间当时确实生效这个偏移，哪个就算一个解
- 夏令时切换规则的落法：开始规则按标准偏移解读（拨快前的当地时刻），结束规则按夏令时偏移解读（拨回前的当地时刻）；结束不晚于开始时按南半球跨年段处理，结束落在下一年；生效年份之外的规则不参与
- 对方那一刻落在夏令时回拨的重复小时里时会有两个解，页面按实际先后都列出来，并写清各自的实际时刻（UTC）、双方当时生效的偏移与我们这边的日期时刻
- 对方那一刻落在夏令时拨快被跳过的时段里时没有解，页面说明这段当地时刻不存在，并给出被跳过的起止时刻
- 每个结果都会再做一遍正推校验：从反推得到的我们这边时刻出发，重新折算回对方当地时刻，必须与输入一致，页面给出这一步校验的结论

## 登记口径

- 时区名称写成地区加城市，例如 `Asia/Shanghai`；基准时可以写 `UTC`；最长 40 个字符，不能重复
- 标准偏移与夏令时偏移都按整数分钟登记，范围是 -720 到 840，带半小时或三刻的地区直接写对应的分钟数（例如东五区半写 330、加德满都写 345）
- 实行夏令时的档案必须填夏令时偏移，且要比标准偏移更大（数值上更靠前）
- 切换规则分开始与结束两段，每段写清月份、第几个星期（一到四或者最后一个）、星期几、小时与分钟
- 生效年份填 1900 到 2100 之间；结束年份留空表示至今有效，已经停止实行夏令时的地区要把结束年份填上
- 备注用来写这条档案需要留意的地方，最长 200 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "zones": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

## 接口一览

| 方法   | 路径             | 说明                                       |
| ------ | ---------------- | ------------------------------------------ |
| GET    | /api/health      | 服务状态检查                               |
| GET    | /api/zones       | 时区档案清单，支持按是否实行夏令时筛选与关键词搜索 |
| POST   | /api/zones       | 新增时区档案                               |
| GET    | /api/zones/:id   | 查看单条档案                               |
| PATCH  | /api/zones/:id   | 修改档案                                   |
| DELETE | /api/zones/:id   | 删除档案                                   |
| POST   | /api/convert     | 把一个时刻换算到所有已登记的时区           |
| POST   | /api/reverse     | 由对方当地时刻反推我们这边的时刻（含夏令时与正推校验） |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
