# tp115 时区与时间换算工作台

一个本地小工具：把各地时区连同夏令时规则登记进来，再把某一个时刻换算到所有已登记的时区，页面上直接看出各地是当地的几点、谁的日期已经翻到前一天或者后一天、跟来源时区差了几个小时。手上只有对方那边定好的当地时刻时，也可以在反推台给出对方时区与时刻，推出我们这边对应的几点几分、哪一天；对方那天正好落在夏令时结束重复的一小时里时，两个对应时刻会按先后全部列出，每个结果都附带一步正推验证。时区名写得不合规矩、偏移超出范围、夏令时偏移不比标准偏移靠前、开始与结束两段规则写得一模一样、结束年份早于开始年份，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5115>

端口固定为 `5115`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 时区档案区列出时区名称、显示名称、标准偏移、是否实行夏令时、夏令时偏移、切换规则、生效年份与备注；可以按是否实行夏令时筛选，也能按名称、显示名或备注搜索
2. 点新建档案填上时区名与偏移；实行夏令时的档案还要把夏令时偏移与开始、结束两段切换规则（第几个星期几的几点几分）以及生效年份填上
3. 换算台选好日期、时刻与来源时区，点换算一遍，页面列出每个已登记时区的当地日期、当地时刻、星期、与来源是否同一天、当时生效的偏移、是否正处在夏令时，以及跟来源时区差多少
4. 反推台填对方那边的当地日期、时刻与对方时区，再选我们这边的时区，点反推我们这边，页面列出我们这边对应的日期、时刻与星期；对方时刻落在重复的一小时里时两个对应时刻按先后全部列出，每个结果都带正推验证的结论
5. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 换算口径

- 夏令时规则按“第几个星期几的几点几分”落到具体日期：开始切换的时刻按标准偏移落地，结束切换的时刻按夏令时偏移落地；南半球夏令时跨年，季节按开始年份归属，开始年份落在生效年份区间内才实行
- 正推（换算台）：来源当地时刻先按来源时区落成实际瞬间，再逐个时区按当时生效的偏移算出当地日期与时刻；来源时刻落在重复的一小时里时按第一次出现换算并在页面上说明，落在被跳过的一小时里时会直接指出该时刻不存在
- 反推（反推台）：给对方时区与那边的当地时刻，用标准偏移与夏令时偏移各试一次并核对，找出对应的实际瞬间，再按我们这边当时生效的偏移算出日期与时刻
- 对方时刻落在重复的一小时里时对应两个实际瞬间，两个都按先后列出，写清各自对应我们这边的实际时刻；落在被跳过的一小时里时当地没有这一刻，页面直接说明
- 每个反推结果都做正推验证：拿我们这边的时间正推回对方当地，得到的当地时刻必须与输入一致，结论显示在页面上
- 与来源时区的时差按两边当时生效偏移的差值给，整小时只写小时，带分钟的把分钟也写出来
- 结果按偏移从小到大排列，来源时区那一条在页面上会标出来

## 登记口径

- 时区名称写成地区加城市，例如 `Asia/Shanghai`；基准时可以写 `UTC`；最长 40 个字符，不能重复
- 标准偏移与夏令时偏移都按整数分钟登记，范围是 -720 到 840，带半小时或三刻的地区直接写对应的分钟数（例如东五区半写 330、加德满都写 345）
- 实行夏令时的档案必须填夏令时偏移，且要比标准偏移更大（数值上更靠前）
- 切换规则分开始与结束两段，每段写清月份、第几个星期（一到四或者最后一个）、星期几、小时与分钟
- 生效年份填 1900 到 2100 之间；结束年份留空表示至今有效，已经停止实行夏令时的地区要把结束年份填上
- 备注用来写这条档案需要留意的地方，最长 200 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "zones": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

## 接口一览

| 方法   | 路径             | 说明                                       |
| ------ | ---------------- | ------------------------------------------ |
| GET    | /api/health      | 服务状态检查                               |
| GET    | /api/zones       | 时区档案清单，支持按是否实行夏令时筛选与关键词搜索 |
| POST   | /api/zones       | 新增时区档案                               |
| GET    | /api/zones/:id   | 查看单条档案                               |
| PATCH  | /api/zones/:id   | 修改档案                                   |
| DELETE | /api/zones/:id   | 删除档案                                   |
| POST   | /api/convert     | 把一个时刻换算到所有已登记的时区           |
| POST   | /api/convert/reverse | 由对方时区的当地时刻反推我们这边对应的日期与时刻，附正推验证 |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
